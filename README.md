# Редакционная аналитика DEMO

Внутренний дашборд для рассылок ГФ и ГЗ.

С 4 сентября 2026 года проект работает по новой архитектуре и **не использует старую таблицу редакционной DEMO-аналитики как источник данных**.

## Источники истины

У сайта два исходных источника:

1. **Sendsay API**.
   - фактические выпуски и метрики читаются напрямую через `stat.uni`;
   - используются LBAC policy `goi = 52` и `mcfr_gos = 61`;
   - в Apps Script нужны Script Properties `SENDSAY_API_KEY` и `SENDSAY_ACCOUNT=actionmedia`;
   - рабочая синхронизация больше не требует `.webarchive`, `.mhtml`, `.mht` на Google Drive;
   - уникальность отправки определяется по `issue.id`.

2. **Исходная Google-таблица «Статистика по ДЕМО»**.
   - из неё берутся R / Y / G и недельные планы;
   - конкретному письму R / Y / G назначаются только при точном совпадении Campaign / UTM;
   - общий план-факт строится заново по шести продуктам.

Служебная таблица `Analytics Center — служебные данные v2` является только техническим хранилищем сайта.

## Каноническое правило NEWS

Новостными считаются **только** два штатных типа Campaign:

- ГФ: `Gosfinansi_letter_news_GF_digest...` из файлов вида `265 | NEWS | Gosfinansi_letter_news_GF_digest...`;
- ГЗ: `letter_news_goszakaz_regular_news_digest...` из файлов вида `729 | News | letter_news_goszakaz_regular_news_digest...`.

`_nd_`, случайное слово `news`, любой другой `digest` и похожие маркеры сами по себе NEWS не делают.

## Главные правила аналитики

- KPI = только Green.
- Yellow = потенциал для дожима.
- Red = диагностический слой, но не выполненный результат.
- Периодика и Системы дозревают около 3 дней.
- Школы дозревают около 6 дней.
- Green всегда исключается из дожима.
- Сначала Yellow, затем при необходимости активные Red.
- Exact-материал и очень близкий сюжет не повторяются в пределах 7 дней.
- Открытия, клики и клики после открытия оцениваются отдельно от Green.

## Синхронизация

Рабочий источник писем — Sendsay API.

- перед переходом есть безопасный тест `testSendsayApiOneDay()`, который только читает 29.09.2026 и ничего не пишет;
- один раз выполняется backfill с **01.07.2026** по текущую дату;
- далее каждый день около **08:00 МСК** перечитываются последние **3 календарных дня**;
- повторное чтение существующего `issue.id` обновляет метрики и не создаёт новый дубль;
- после API-синхронизации пересчитывается DEMO-срез;
- legacy-код чтения файлов Drive временно оставлен как резерв.

## Статус импорта

В служебном разделе отдельно показываются:

- **Файлов загружено** — все текущие сохранённые файлы, включая дубли и ошибки;
- **Уникальных отправок** — канонические Sendsay Campaign ID;
- ошибки;
- дубли;
- DEMO связано;
- без связи;
- удалено;
- последняя дата отправки и время последнего импорта.

Поэтому загрузка нового дубля теперь видна как новый файл, даже если число уникальных отправок не изменилось.

## Публикация

После перехода на Sendsay API:

1. Убедиться, что в Apps Script заданы `SENDSAY_API_KEY` и `SENDSAY_ACCOUNT=actionmedia`.
2. Сначала запустить `testSendsayApiOneDay()` и сверить несколько писем с Sendsay/DEMO.
3. Только после успешной сверки запустить `setupSendsayApiMigration()`.
4. Дождаться завершения backfill с 01.07.2026.
5. Проверить DEMO-сопоставление и метрики.
6. После контрольной сверки старые `.webarchive/.mhtml/.mht` можно удалить с Drive.
7. Ежедневное обновление выполняется автоматически около 08:00 МСК и перечитывает последние 3 дня.

`setup()` при каждом обновлении запускать не нужно.
