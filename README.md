# Редакционная аналитика DEMO

Внутренний дашборд для рассылок ГФ и ГЗ.

С 4 сентября 2026 года проект работает по новой архитектуре и **не использует старую таблицу редакционной DEMO-аналитики как источник данных**.

## Источники истины

У сайта два исходных источника:

1. **Sendsay API**.
   - фактические выпуски и метрики читаются напрямую через `stat.uni`;
   - используются LBAC policy `goi = 52` и `mcfr_gos = 61`;
   - в Apps Script нужны Script Properties `SENDSAY_API_KEY` и `SENDSAY_ACCOUNT=actionmedia`;
   - рабочая синхронизация больше не требует `.webarchive`, `.mhtml`, `.mht` на Google Drive;
   - уникальность отправки определяется по `issue.id`.

2. **Исходная Google-таблица «Статистика по ДЕМО»**.
   - из неё берутся R / Y / G и недельные планы;
   - конкретному письму R / Y / G назначаются только при точном совпадении Campaign / UTM;
   - общий план-факт строится заново по шести продуктам.

Служебная таблица `Analytics Center — служебные данные v2` является только техническим хранилищем сайта.

## Торговые письма: Market / Project / Event

Вкладка «Торговые письма» отдельно показывает email-выпуски ГФ и ГЗ за тот же
отчётный период, что DEMO: **начиная с недели W27 2026 (29.06.2026)**.
Политики Sendsay уже настроены для API-загрузки DEMO:

- goi / LBAC 52 → ГФ (Госфинансы);
- mcfr_gos / LBAC 61 → ГЗ (Госзаказ).

Новых аккаунтов или ключей не требуется. Используются существующие Script Properties
SENDSAY_API_KEY и SENDSAY_ACCOUNT.

Отбор делается по точным меткам **Market**, **Project**, **Event** из полей
issue.label0–issue.label9 в Sendsay API (stat.uni). Нельзя заменять
их поиском подстрок в Campaign или в теме. Письмо с двумя метками учитывается
один раз по паре lbac.policy + issue.id. Личные тесты, не-email и отправки
до 29 июня 2026 исключаются.

Технические листы «_Торговые письма» и «_Торговые письма staging» независимы
от «_Sendsay v2». Факт доставки, открытия, клики, OR, CTR и CTOR не смешиваются
с DEMO R/Y/G, не влияют на план или фактический результат.

### Развёртывание

1. Добавить новый серверный файл TradeEmails.gs в действующий Apps Script.
2. Обновить в том же Apps Script Code.gs и PublicRead.gs, чтобы включить
   публичный read-only метод getTradeMailUi. Обновление исходников на
   GitHub **не заменяет** обновление Apps Script.
3. Сохранить новую версию развертывания Apps Script Web App.
4. Войти в Analytics Center владельцем, открыть «Торговые письма» и выбрать
   «Загрузить историю с 27-й недели». Сервер будет читать данные порциями;
   рабочая таблица заменится только после полного прохода.
5. Один раз в Apps Script выполнить installTradeMailDailyTrigger(). Это
   отдельный запуск около 08:35 МСК, обновляющий 3 последних дня и не
   мешающий основному DEMO-триггеру.

Загрузка за три дня **не** заменяет первоначальную полную загрузку с W27.
Кнопка «Перечитать данные» обновляет отображение, не обращаясь к API Sendsay.

### ВИО: детализация первой пятёрки тем

Под разделом «Большие темы» добавлены раскрывающиеся аналитические карточки
**первых пяти предметных тем** текущего месяца отдельно для ГФ и ГЗ.
Категория «Другие вопросы» не занимает одно из пяти мест.

Внутри каждой крупной темы анализируются **конкретные подтемы** по текстам
заголовков и вопросов: например, для 223-ФЗ это положение о закупке,
закупки у единственного поставщика, способы закупок, заявки и требования
к участникам, договоры, оплата, ЕИС, МСП и нацрежим.

Показатели каждой подтемы:
- уникальные вопросы за каждый месяц август–ноябрь 2026;
- доля внутри родительской темы в последнем месяце;
- изменение доли к предыдущему месяцу (п.п.);
- отдельная строка «Прочие», а не искусственная стопроцентная классификация.

Используется однозначный классификатор: один вопрос попадает ровно в одну
подтему. Для 223-ФЗ выделены сомнительные записи с явным упоминанием 44-ФЗ
без упоминания 223-ФЗ; исходные вопросы при этом не удаляются и не
переносятся между крупными темами без проверки рубрики. Самих текстов
вопросов в JSON-выгрузке нет.

Расчёт включён в \`VioTrends.gs\`, а агрегированные значения уже опубликованы
в \`vio-trends.json\`. Для автоматического пересчёта из Google Sheets после
новых выгрузок необходимо обновить серверный \`VioTrends.gs\` в Apps Script.

## Каноническое правило NEWS

Новостными считаются **только** два штатных типа Campaign:

- ГФ: `Gosfinansi_letter_news_GF_digest...` из файлов вида `265 | NEWS | Gosfinansi_letter_news_GF_digest...`;
- ГЗ: `letter_news_goszakaz_regular_news_digest...` из файлов вида `729 | News | letter_news_goszakaz_regular_news_digest...`.

`_nd_`, случайное слово `news`, любой другой `digest` и похожие маркеры сами по себе NEWS не делают.

## Главные правила аналитики

- KPI = только Green.
- Yellow = потенциал для дожима.
- Red = диагностический слой, но не выполненный результат.
- Периодика и Системы дозревают около 3 дней.
- Школы дозревают около 6 дней.
- Green всегда исключается из дожима.
- Сначала Yellow, затем при необходимости активные Red.
- Exact-материал и очень близкий сюжет не повторяются в пределах 7 дней.
- Открытия, клики и клики после открытия оцениваются отдельно от Green.

## Синхронизация

Рабочий источник писем — Sendsay API.

- перед переходом есть безопасный тест `testSendsayApiOneDay()`, который только читает 29.09.2026 и ничего не пишет;
- один раз выполняется backfill с **01.07.2026** по текущую дату;
- далее каждый день около **08:00 МСК** перечитываются последние **3 календарных дня**;
- повторное чтение существующего `issue.id` обновляет метрики и не создаёт новый дубль;
- после API-синхронизации пересчитывается DEMO-срез;
- legacy-код чтения файлов Drive временно оставлен как резерв.

## Статус импорта

В служебном разделе отдельно показываются:

- **Файлов загружено** — все текущие сохранённые файлы, включая дубли и ошибки;
- **Уникальных отправок** — канонические Sendsay Campaign ID;
- ошибки;
- дубли;
- DEMO связано;
- без связи;
- удалено;
- последняя дата отправки и время последнего импорта.

Поэтому загрузка нового дубля теперь видна как новый файл, даже если число уникальных отправок не изменилось.

## Публикация

После перехода на Sendsay API:

1. Убедиться, что в Apps Script заданы `SENDSAY_API_KEY` и `SENDSAY_ACCOUNT=actionmedia`.
2. Сначала запустить `testSendsayApiOneDay()` и сверить несколько писем с Sendsay/DEMO.
3. Только после успешной сверки запустить `setupSendsayApiMigration()`.
4. Дождаться завершения backfill с 01.07.2026.
5. Проверить DEMO-сопоставление и метрики.
6. После контрольной сверки старые `.webarchive/.mhtml/.mht` можно удалить с Drive.
7. Ежедневное обновление выполняется автоматически около 08:00 МСК и перечитывает последние 3 дня.

`setup()` при каждом обновлении запускать не нужно.
